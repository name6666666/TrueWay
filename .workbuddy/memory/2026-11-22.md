## 类型包评估：rmmz/lib/extra.d.ts 是否该修

- 项目依赖 `rmmz: file:rmmz`，实际是 `@comuns-rpgmaker/rpg-maker-mz-typescript@0.1.2`（2020 年，半成品）。
- 用本机 MZ 1.0.0 引擎源码（`G:/rpg project/project3/js/*.js`）做基准，解析 `Xxx.prototype.m =` 得到 159 类 / 3993 成员，对比各包成员覆盖：
  - 当前包 + extra.d.ts：49%（63 个类完全缺失），另有 149 个「引擎里不存在」的成员（MV 遗留/臆造，如 `mapX/realX/breadthPercent/isMultiFloor/requestMove/arePageConditionsMet/isPlayTest`，以及虚假全局 `$gameEvent/$gameFollowers/$gameVehicles/$gameCharacterIndex`）。
  - `rmmz-types@1.5.0-3`（Vilja，MIT）：96%，只系统性缺各处 `initialize()`（134 个类），构造函数参数/枚举类型准确，带 PIXI 6 类型依赖。
  - `@rpgmts/types-mz@1.1.0`：86%，由 JS 自动生成，`any` 占满（0/3366 已标注），且是全局声明（无模块导出），与现有 `import mz from 'rmmz'` + `declare module 'rmmz'` 写法不兼容。
  - `rmmz-typescript@2.3.5`：57%，是 0.1.2 的同源分支。
- 结论：**换包（选 rmmz-types）优于修 extra.d.ts**。因为外层包自身有内部矛盾（`Game_Actor.isActor(): true` 与 `Game_Battler` 的类型谓词冲突 → 连带 `rmmz_objects/Game_Troop.ts` 报 TS2344，skipLibCheck=false 时构建失败），声明合并也补不回来。
- 迁移动点：`rmmz/lib` 换成 Vilja 的 lib + 一个 `export default`（`typeof import('./index')`）shim 以保留 `import mz from 'rmmz'`；`storage.ts` 的 `SavefileContent` → `SaveContents`；`true-way.ts` 里 `$dataMap[info.id]` 是**真 bug**（`$dataMap` 是单个地图对象，不是数组），应改成 `$dataMap.events`。
- 已验证：同一份 src 用 rmmz-types 编译只剩上述 3 个错误（`skipLibCheck: true`）。

## 换包的具体接法（已实测）

- 用 npm 别名保住模块名：`"rmmz": "npm:rmmz-types@1.5.0-3"`（`npm i rmmz@npm:rmmz-types@1.5.0-3 --save-exact`）。node_modules/rmmz 即 rmmz-types，`import mz from 'rmmz'`、`declare module 'rmmz'`、rollup 的 `external/globals: {rmmz:"window"}` 全部不用改。
- 版本必须精确写 `1.5.0-3`（预发布号），不要 `^`。
- 必须开 `esModuleInterop`（或 `allowSyntheticDefaultImports`），否则 `import mz from 'rmmz'` 报 TS1192 —— rmmz-types 没有默认导出。
- 提示：本项目目前没有 tsconfig.json，rollup 插件走默认选项；建议补一个 tsconfig 显式写 compilerOptions，别依赖插件默认值。

## true-way.ts 里「遍历所有地图事件」的问题

- 现在模块顶层那个 for 循环**一定崩**，三个独立原因：
  1. `$dataMapInfos` 在插件脚本执行时还是 `null`（rmmz_managers.js 开头就是 `$dataMapInfos = null`，要等 Scene_Boot → `DataManager.loadDatabase` 才有值），`for...of null` 直接抛；
  2. `$dataMap` 是**当前这一张**地图对象，不是数组，`$dataMap[info.id]` 恒为 undefined；
  3. 引擎运行时内存里只有一张地图，`DataManager.loadMapData` 在传送时才读 `data/MapNNN.json` 覆盖 `$dataMap`，所以没有「全量事件编号」的现成 API。
  4. `DataManager.createGameObjects`（setupNewGame / loadGame / battle test / event test 都走它）才是数据库就绪后的安全时机。
- 推荐改法：不枚举，`_data[mapId][eventId]` 懒建（`mapDataOf()` / `eventDataOf()`），Proxy 里改成读懒建后的 scope。
- 需要全量表时：① 钩 `DataManager.isDatabaseLoaded`，用官方 `DataManager.loadDataFile(name, src)` 逐图加载（`'Map%1.json'.format(id.padZero(3))`，data/ 前缀与解析都由引擎做），在 alias 过的 `DataManager.onXhrLoad` 里读已解析好的 `window[name]` 并置空回收；② 构建期用 node 读工程 data 目录生成常量表（build.js 已知道工程路径）。只关心当前地图则 alias `Game_Map.prototype.setup`（此时 `$dataMap` 已是新图）。
- 这两个官方 loader 都返回 `void`：结果写进全局槽位——`loadMapData(mapId)` → `$dataMap`（只有一个槽，循环调用会互相覆盖，且会破坏当前地图），`loadDataFile(name, src)` → `window[name]`（可以自定义 N 个槽，这才是批量收集的正确用法）。异步完成判定：`DataManager.isMapLoaded()` 即 `!!$dataMap`，Scene_Map 也是轮询它。

### 进入地图的官方回调（MZ 1.0.0 实测时序）

传送：`reserveTransfer` → 淡出 → `Scene_Map.create`（`loadMapData(newMapId)` 异步开始 + `onTransfer` 清缓存）→ 每帧 `isReady()` 轮询 `isMapLoaded()` → `onMapLoaded`（先 `performTransfer` → `$gameMap.setup` + `locate`，再 `createDisplayObjects`）→ `start` → `onTransferEnd`（地图名窗口 + `$gameMap.autoplay()` + 自动存档）。
首次进图/读档：`create` 时 `_transfer=false`，只 `loadMapData($gameMap.mapId())`，之后 `onMapLoaded`，但**不会**走 `onTransferEnd`。
- `Game_Map.prototype.setup(mapId)`：最底层的「地图对象初始化」，`$dataMap` 已就绪，进图/读档/传送都走；插件里最通用。
- `Scene_Map.prototype.onMapLoaded`：数据就绪 + 建显示对象前，首次进图与传送都触发。
- `Scene_Map.prototype.onTransferEnd`：仅传送/换图触发，位置已设好，引擎自己在这做 autoplay/autosave。
- `Scene_Map.create` 里不能读 `$dataMap`（那时异步加载才刚开始）。
